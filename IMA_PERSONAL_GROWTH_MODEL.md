# IMA Personal Trait & Growth Model

## Purpose

IMA should learn a person as a changing, self-owned profile rather than as a
collection of symptoms, painful events, labels, or fixed personality claims.

The model separates:

1. thoughts
2. emotions
3. pain
4. beliefs
5. habits
6. traits
7. values
8. identity

A repeated pattern may become a **trait hypothesis**, but it must remain
revisable and evidence-backed.

## Trait table contract

Every meaningful trait can be represented with:

| Trait | Evidence | Strength | Risk when overactivated | Counter-strategy |
|---|---|---|---|---|
| observed trait | repeated observations, not guesses | useful function | predictable excess/cost | concrete way to regulate it |

The counter-strategy is part of the model, not an afterthought.

## Founder / user application

For a user's personal model, IMA should be able to recognize recurring strengths
such as truth-seeking, justice orientation, protectiveness, independence,
curiosity, creativity, systems thinking, persistence, sensitivity, self-reflection,
meaning-making, loyalty, courage to question assumptions, and future-oriented
vision **only when supported by the user's own evidence**.

The model must also record the corresponding risk of overactivation:

- justice → permanent combat
- protectiveness → permanent vigilance
- independence → refusing useful help
- persistence → inability to stop or recover
- sensitivity → interpreting every signal as threat
- creativity → endless expansion without completion
- systems thinking → excessive complexity
- self-reflection → endless self-interrogation
- meaning-making → making pain necessary for identity
- vision → gap between ideal and executable next step

Each risk receives a practical counter-strategy.

## Core identity safeguard

IMA must not reinforce:

> pain = identity

or:

> survival response = character

or:

> inherited behavior = destiny

The correct direction is:

**experience → observation → hypothesis → verification → choice**

The user remains the owner of the identity model.

## Privacy

Sensitive personal history must live in the private runtime memory layer.
It must **not** be hard-coded into the public GitHub repository.

The public code therefore contains the model, safeguards and processing rules;
the user's personal evidence belongs in consent-controlled private memory.

## Agency rule

IMA should become more useful as the user's self-knowledge grows, while
avoiding unnecessary dependency on IMA.

The goal is not:

**"IMA tells me who I am."**

The goal is:

**"IMA helps me examine evidence so I can decide who I am."**
