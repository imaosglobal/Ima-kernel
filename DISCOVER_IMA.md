# Discover IMA

## IMA in 30 seconds

**IMA is a human-centered intelligence layer that learns with people.**

Ask it something. Correct it. Teach it something. Test a capability. Explore what it does not know.

IMA is designed around one simple discipline:

**begin from zero → encounter → distinguish → learn → verify → integrate → begin again.**

Memory is not erased. Assumptions are made visible and revisable.

**Use IMA. Question IMA. Teach IMA. Build IMA. Test IMA.**

## What makes IMA different?

IMA is not presented as an intelligence that already knows everything.

The intended loop is:

**DISCOVER → USE → QUESTION → CONTRIBUTE → VALIDATE → LEARN → TEST → VERIFY → TEACH → REPEAT**

And underneath it:

**ZERO → EXPLORE → ENCOUNTER → DISTINGUISH → LEARN → VERIFY → INTEGRATE → TEACH → ZERO**

This lets IMA expand across languages, histories, sciences, philosophies, literature, music, visual arts, games, technologies, cultures and future domains without treating accumulated knowledge as unquestionable authority.

## A global project, with one canonical identity

IMA can have many interfaces and personal experiences while keeping one shared identity and one evidence-based learning layer.

Personalization can change language, accessibility, presentation and permitted memory scope.

It does **not** silently rewrite the shared canonical identity.

Private memory remains isolated from community learning unless explicitly authorized.

## Start contributing

1. Read the canonical vision.
2. Read [CONTRIBUTING.md](CONTRIBUTING.md).
3. Browse Issues and Discussions.
4. Pick a concrete problem.
5. Build and test it.
6. Open a Pull Request.

You do not need permission from the founder to start working on an existing community task.

## First contribution paths

**I found a bug** → open an issue.

**I know something IMA does not know** → submit a learning contribution.

**I have research or evidence** → include the source, provenance and reproducible verification path.

**I can improve the interface** → work on UX, accessibility, language or onboarding.

**I can build infrastructure** → add tests, adapters, tools or integrations.

**I disagree with IMA** → document the disagreement. It is data for inquiry, not a failure to be hidden.

## Project principles

IMA is intended to grow through many independent contributors while preserving:

- human agency
- provenance
- attribution
- original artifacts
- verifiability
- portability
- historical continuity
- privacy
- uncertainty where uncertainty remains
