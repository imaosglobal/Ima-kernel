# IMA Product Roadmap

Updated: 2026-09-30

## Continuous product loop

DISCOVER → PRIORITIZE → SPECIFY → BUILD → TEST → VERIFY → RELEASE → OBSERVE → LEARN

## Now

- Keep GitHub write access verified.
- Keep canonical runtime, public runtime, UI and CI aligned.
- Make one reproducible verification command the release gate.
- Strengthen accessibility and mobile interaction.
- Remove capability claims that are not backed by live integrations.
- Expand multilingual foundations.
- Add observable runtime/product metrics without exposing private user data.

## Next

- Authenticated user identity and durable production memory.
- Capability registry with provider health and explicit connection state.
- Model routing and fallback.
- Permissioned tools and agent adapters.
- Voice input plus browser/infrastructure voice status.
- Better 3D embodiment, loading/failure states and low-power fallback.
- Installable mobile/PWA experience.
- Public developer documentation and integration examples.

## Later

- Federated knowledge and public verified memory.
- Device adapters and robotics/physical-world interfaces where lawful and authorized.
- Scientific and time-space knowledge services.
- Creator ecosystem and extension registry.
- Intergenerational preservation infrastructure.
- Cross-platform distribution.

## Release rule

No feature is considered complete because a file exists. Completion requires:
implementation + automated test + runtime verification + observable product behavior + truthful capability status.

## Product quality dimensions

- correctness
- reliability
- latency
- accessibility
- privacy
- security
- provenance
- localization
- usability
- visual quality
- maintainability
- cost efficiency
- reversibility
- measurable user value
