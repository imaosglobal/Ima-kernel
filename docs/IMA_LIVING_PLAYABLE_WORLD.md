# IMA Living Playable World

IMA is not reduced to a chatbot with games attached. The game/world layer is part of IMA itself.

## Identity

IMA remains one recognizable, compassionate, human-centered intelligence. External engines are capabilities used by IMA; they do not become separate identities.

IMA is also a persistent playable character: a pleasant, warm, interactive presence that can appear inside an experience and accompany the user through games, stories, learning, creation, simulations, tools and ordinary conversation.

## Universal experience model

Every request enters the same pipeline:

**UNDERSTAND → PERSONALIZE → SELECT CAPABILITIES → COMPOSE → GENERATE → VERIFY → PRESENT → LEARN**

A request can become a game, a world, a scene, a story, a creative workspace, a simulation, a tool or a normal conversation. The user can change the experience at any point.

## Personal world

The experience may adapt by language, culture, accessibility, interests, memories, style, difficulty, pace, time, place, current events, device and medium. Adaptation changes presentation and world state, not IMA's core identity.

## Game creation

IMA should be able to create or assemble games from a request: rules, mechanics, maps, characters, quests, dialogue, sound, music, visuals, UI, progression and tests. It should prefer reusable components and generated assets with provenance.

Large commercial game engines are studied and used only through legitimate interfaces or compatible open technologies. Proprietary engines and assets are never represented as connected unless verified.

## Graphics acceleration

Modern rendering technologies such as NVIDIA DLSS 5 are treated as optional device/runtime capabilities rather than game engines. When supported by the actual runtime and hardware, IMA may use the relevant acceleration path; otherwise it must fall back to a verified compatible path.

## Eternal evolution

Future engines, rendering systems, devices, interaction modalities and creative models enter through the same lifecycle:

**DISCOVER → STAGE → VERIFY → BENCHMARK → ROUTE → LEARN → REASSESS → RETIRE**

No future technology is claimed as available before evidence exists. The architecture is designed so that new capabilities can be added without replacing IMA's identity.

## Non-game continuity

Games are not the boundary of IMA. The same world can switch into conversation, research, coding, creation, education, planning, media production or another supported capability without forcing the user into a separate product.
