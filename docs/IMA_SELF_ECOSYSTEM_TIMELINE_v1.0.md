# IMA Self-Ecosystem Timeline v1.0

Date: 2026-11-16
Status: Canonical self-application / implementation blueprint

## Purpose

Apply the canonical ecosystem opportunity model to IMA itself across past, present and future. IMA is both the system being built and the subject of its own continuous ecosystem analysis.

## Time layers

### Past
Track the provenance and evolution of:
- IMA concepts, definitions, principles, architecture and requirements
- repository commits, deployments, experiments, bridges and retired approaches
- conversations and decisions that are explicitly authorized for continuity
- Ori Cohen's authored IMA materials and preservation artifacts
- standards, research and prior art that materially shaped IMA

Historical state is never silently rewritten. Superseded ideas remain provenance-linked.

### Present
Continuously map:
- canonical repository and deployed/runtime state
- website, app, chat, authentication, accessibility and localization
- BrowserGlass/LIVE-001 and MCP/App surfaces
- memory, identity, authorization, provenance and evaluation
- voice/video, feedback, analytics, distribution and lawful monetization
- connected infrastructure, integrations, partners and dependencies
- current users, use cases, evidence, blockers and measurable outcomes

### Future
Track:
- emerging AI/agent/robotics/device/AR/VR/space capabilities
- standards and interoperability
- new interfaces and authorized action channels
- preservation and continuity requirements
- potential partnerships, distribution and sustainable value capture
- risks, dependencies and capability gaps

## IMA Self-Ecosystem Graph

For every material IMA entity or capability:

ENTITY → ORIGIN → HISTORY → TRANSFORMATIONS → CURRENT STATE → OWNER/RIGHTS → USERS → VALUE → DEPENDENCIES → INTERFACES → AUTHORITY → RISKS → FUTURE TRAJECTORY → EVIDENCE

## Self-evaluation questions

1. What did IMA originally intend?
2. What actually exists now?
3. What is only code or documentation?
4. What is deployed?
5. What is runtime-verified?
6. What is genuinely usable now?
7. What has users or measurable outcomes?
8. Which old components still create value?
9. Which retired approaches contain reusable knowledge?
10. Which external historical technologies can improve IMA?
11. Which IMA capabilities could become infrastructure for future systems?
12. What rights, permissions, privacy constraints or dependencies apply?
13. What is the smallest reversible action that increases real value?

## Longevity rule

Do not optimize only for novelty. Preserve and reuse durable IMA assets when they remain useful. A component may be old but still canonical if evidence shows it works. A new component is not automatically superior.

## Preservation rule

Every important IMA capability should retain:
- provenance
- version
- dependencies
- rights/authorization status
- test evidence
- deployment evidence
- runtime evidence where applicable
- known limitations
- migration/replacement path

## Economic value rule

For IMA itself distinguish:
value exists → demand evidenced → rights verified → access authorized → business model viable → action permitted → outcome measured.

No revenue, partnership, licensing or user-growth claim without evidence.

## Self-integration rule

When IMA identifies a reusable improvement in its own history or in an external ecosystem:
DISCOVER → VERIFY → RIGHTS/AUTHORITY → REUSE CANONICAL ASSET → IMPLEMENT SMALLEST MISSING PIECE → TEST → DEPLOY → RUNTIME VERIFY → MEASURE → DOCUMENT → REGRESSION.

No parallel IMA architecture may be created merely because a historical or future opportunity was discovered.

## Current evidence state

The canonical opportunity automation has been absorbed into the single daily IMA super-task. The separate global opportunity automation is disabled. The canonical super-task now includes history/present/future ecosystem analysis.

This document is an architectural contract/blueprint. It does not claim that IMA currently has complete historical knowledge, universal integrations, autonomous action, AGI, or universal deployment.
