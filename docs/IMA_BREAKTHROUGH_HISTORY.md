# IMA — Historical Breakthrough Record
## פריצות הדרך ההיסטוריות של IMA והלקחים לתכנון עתידי

**Purpose:** לשמר בתוך IMA את הדרך שעברנו בפועל, כדי שכל תכנון עתידי יתחיל ממה שכבר הוכח כאפשרי — ולא יחזור להנחות הישנות של "אי אפשר".

**Principle:**  
> אמת לפני הכרזה. כל הישג היסטורי נרשם בנפרד מיכולת שעדיין דורשת הוכחה.

## 1. ממצב של רעיון למאגר קוד ממשי

IMA עברה מרעיון ומסמכי חזון למאגר GitHub ממשי:
- `imaosglobal/Ima-kernel`
- נוצרה היררכיית קוד, runtime, זיכרון, learning, UI, governance, CI/workflows ו-connectors.
- נקבעה דרך עבודה סביב מקור קוד קנוני, במקום לבנות עוד ועוד מערכות מקבילות.

**לקח:** לפני כל פיתוח חדש יש לזהות את המקור הקנוני ולמנוע פיצול.

## 2. זיהוי המקור הקנוני והפסקת ערבוב בין מערכות

במהלך אוגוסט–ספטמבר 2026 זוהה `~/Ima-kernel` כנתיב Git הקנוני, בעוד `~/ima_kernel` זוהה כ-wrapper/symlink שאינו המקור הקנוני, ו-`kernel/projects/ima_core` כמבנה נפרד.

נמצאו גם רכיבים כפולים/מתנגשים, כולל runtime-ים, package files ו-deployment scripts.

**פריצת דרך:** במקום להעמיד פנים שהכול מערכת אחת, התחלנו למפות מה קיים באמת.

**לקח:** כל אינטגרציה עתידית מתחילה ב-inventory, ownership, canonical path ו-source of truth.

## 3. מעבר מ"אוטונומיה מדומה" לאמת הנדסית

**פריצת דרך:** IMA למדה להבדיל בין:
- קוד שקיים,
- קוד שמופעל,
- קוד שמדמה פעולה,
- פעולה שבוצעה בפועל,
- יכולת שעדיין לא הוכחה.

**לקח:** שום רכיב לא ייחשב "פעיל" רק משום שקיים קובץ, workflow או מסמך שמתאר אותו.

# מה למדנו מהפריצות האלה

## כלל 1 — לא להכריז על הצלחה לפני בדיקה
"נכתב", "נבנה", "committed", "deployed", "published", "accessible", "working" ו-"trusted" הם מצבים שונים.

## כלל 2 — מקור אמת אחד
כל feature חדש חייב לדעת:
1. איפה הקוד הקנוני.
2. איפה הנתונים הקנוניים.
3. מה הכתובת הציבורית הקנונית.
4. מה מצב הפריסה.
5. מה בדיקת הקבלה שלו.

## כלל 3 — כל מערכת מקבלת Proof Loop
**Plan → Implement → Commit → Deploy → Open public URL → Test real user path → Record evidence → Only then declare success.**

## כלל 4 — שני קולות גם בהנדסה
כמו המבוגר והילד:
- "הקול המפחד": מה עלול להשתבש?
- "הקול המבוגר": מה אנחנו יודעים, מה אפשר לבדוק ומה הפעולה הבאה?

כך IMA לא צריכה לבחור בין אופטימיות לפחד; היא יכולה להפוך את הפחד למנגנון בדיקה.

## כלל 5 — תיעוד אינו ארכיון מת
כל פריצת דרך צריכה להוליד:
- מה חשבנו שאי אפשר.
- מה עשינו.
- מה באמת עבד.
- מה לא עבד.
- איזה evidence קיים.
- מה למדנו.
- איך זה משנה את התכנון הבא.
