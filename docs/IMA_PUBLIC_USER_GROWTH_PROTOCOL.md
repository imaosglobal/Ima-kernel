# IMA Public User Growth Protocol

## Objective

Make IMA easy for the right people to discover, try, understand and return to — without spam, manipulation or false claims.

## Child-first and intergenerational growth

Growth is a by-product of usefulness and trust, not the goal at any cost. Children require age-appropriate experiences, data minimization, non-manipulative design, no dependency-building, and caregiver/educator involvement where appropriate. Do not market emotional exclusivity to children or use child-targeted dark patterns. Do not scale child-facing acquisition until the safety, privacy, accessibility and independent-review gates in [the Intergenerational Global Action Plan](IMA_INTERGENERATIONAL_GLOBAL_ACTION_PLAN.md) pass.

Word-of-mouth must be user-initiated: sharing, invitation or referral happens only after an explicit user action. Never upload contact books, message people automatically, create fake testimonials, or imply an institution endorses IMA without written permission. Measure voluntary referrals and useful outcomes, not time spent in chat.

## Growth funnel

DISCOVER → LAND → UNDERSTAND → TRY → FIRST VALUE → RETURN → CONTRIBUTE → INVITE

### Discover
Use public search indexing, a shareable landing page, open-source visibility, useful public documentation, accessibility communities, developer ecosystems, research communities, educational communities and legitimate partnerships.

### Land
The public site must immediately communicate:
- what IMA is
- what a person can do now
- how to start
- what is private
- what is verified
- how to contribute

### Try
The first interaction should require minimal setup and provide a useful, honest capability.

### First value
Measure whether a new visitor reaches a meaningful first result rather than merely viewing a page.

### Return
Improve conversation quality, continuity, accessibility, performance and usefulness based on consented, privacy-preserving evidence.

### Contribute
Give people a clear way to report errors, teach, translate, test, build adapters and suggest improvements.

### Invite
Provide voluntary sharing and referral paths. Never send unsolicited bulk messages or impersonate people or organizations.

## Acquisition readiness gate

Do not deliberately scale traffic until these are checked:
- public deployment is live
- mobile experience works
- primary conversation path works
- API/runtime health is known
- fallback behavior is understandable
- privacy boundaries are visible
- capability claims are evidence-based
- accessibility basics pass
- indexing metadata exists
- robots.txt and sitemap exist
- errors are observable
- onboarding has a clear first action
- user feedback path exists

## Measurement

Prefer privacy-preserving aggregate signals:
- landing visits
- first interaction
- successful first response
- returning users
- language/device/accessibility coverage
- runtime errors
- abandoned interaction points
- contribution/correction volume
- verified improvements

Do not collect or expose unnecessary personal data.

## Distribution principle

The target is not maximum traffic at any cost. The target is a growing population of people for whom IMA is genuinely useful.

Global reach should grow through legitimate discovery, voluntary use, useful integrations, open contribution, partnerships and platform distribution.

## Continuous loop

Every growth cycle must feed product improvement:

TRAFFIC → EXPERIENCE → EVIDENCE → FRICTION → FIX → VERIFY → BETTER EXPERIENCE

A marketing claim is never a substitute for a working capability.
