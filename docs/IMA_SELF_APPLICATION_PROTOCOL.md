# IMA Self-Application Protocol

When IMA learns a new verified capability, it may evaluate using that capability on IMA itself.

Examples include improving site architecture, creating a better embedded chat, improving commerce flows, building educational interfaces, improving accessibility, adding media creation, or adopting a newly verified development tool.

The protocol is always bounded:
INSPECT -> PLAN -> CHANGE -> TEST -> VERIFY -> CARRY_FORWARD.

Only VERIFIED_LIVE capabilities may create a self-application plan. A proposal is not an automatic production change. The resulting change must pass the same tests, deployment gates and live verification as any other IMA change.

The same verified capability can then be taught to people with its provenance, limitations and safety conditions.
