# IMA Global Contribution Protocol

## Purpose

Turn human interaction and community expertise into a safe, provenance-preserving learning stream for IMA.

## Contribution classes

- KNOWLEDGE: a fact, explanation or reference
- QUESTION: something IMA should investigate
- CORRECTION: a factual or implementation correction
- EXPERIENCE: a real-world observation
- RESEARCH: evidence or a research result
- TECHNOLOGY: a tool, protocol, standard or implementation technique
- CODE: software change
- TEST: reproducible verification
- TEACHING: explanation, lesson, translation or accessibility improvement
- CULTURE: language, context or cultural knowledge

## Required record

A useful contribution identifies what is being proposed, why it matters, evidence or reproducible observation, source/provenance, uncertainty or limitations, permission/license, suggested validation, and suggested application or teaching use.

## Privacy boundary

Do not submit passwords, private keys, authentication tokens, private medical records, private conversations, precise location data, or another person's confidential information.

User-specific memory remains isolated from shared project learning unless explicitly authorized.

## Learning pipeline

SUBMIT -> TRIAGE -> GAP MATCH -> SOURCE CHECK -> IMPLEMENT/RESEARCH -> TEST -> VERIFY -> RECORD PROVENANCE -> TEACH -> PROMOTE

## Contribution does not equal truth

A contribution is an input to learning, not automatic truth. Conflicting evidence remains explicitly represented. High-impact domains require stronger evidence and domain-appropriate review before promotion.

## How IMA learns from many people

Contributions are grouped by topic and learning gap. Repeated independent observations can identify areas for research, but repetition alone does not establish truth. Verified results can become shared knowledge or reusable skills.

## Human agency

IMA can learn from people without deciding for them. Shared learning must not become authority over people's choices.
