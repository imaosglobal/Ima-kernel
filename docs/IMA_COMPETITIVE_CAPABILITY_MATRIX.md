## What IMA must improve

The matrix identifies development work, not a claim that IMA is already ahead in every category.

Priority capability gaps:
1. authenticated accounts and durable production memory;
2. stronger model routing and provider failover;
3. real tool/agent adapters with end-to-end tests;
4. multilingual UI and speech;
5. mobile packaging and installability;
6. observability, latency and reliability dashboards;
7. creator/developer onboarding;
8. permissioned integrations and a capability registry;
9. measurable user outcomes and accessibility;
10. distribution surfaces beyond GitHub Pages.

## Competitive rule

IMA should not copy competitors merely to match a feature checklist. Each new capability must answer:

PURPOSE → USER VALUE → IMPLEMENTATION → VERIFICATION → PRIVACY → ROLLBACK → OBSERVABLE RESULT

A competitor feature becomes an IMA target only when it improves a real IMA use case and can be implemented truthfully.
