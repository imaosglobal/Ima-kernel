# IMA Daily Loop Integration Protocol

The existing **IMA Global Health Loop — לולאת התפתחות מאוחדת** is the single cross-domain daily orchestrator.

## Automatic intake rule
Every newly verified progress item from any IMA workstream is eligible for automatic intake into the existing loop. No second daily orchestrator is created.

## Intake sequence
1. Discover new evidence/change.
2. Validate provenance and reproducibility.
3. Classify status: PLANNED, ATTEMPTED, EXECUTED, VERIFIED, FAILED, GAPS_RECORDED.
4. Apply human-agency and truth gates.
5. Deduplicate against canonical state.
6. Record verified evidence.
7. Feed the verified delta into the existing daily loop.
8. Reprioritize the next cycle.
9. Re-test affected capabilities.
10. Record the outcome and remaining gaps.

## Global integration workstream
External organizations, developers, research groups, public-benefit bodies and voluntary human integrations are treated as one expandable workstream with the same evidence states:
DISCOVERED → ELIGIBLE_PATH_FOUND → PREPARED → AUTHORIZED → CONNECTED → VERIFIED.

Only AUTHORIZED/CONNECTED/VERIFIED evidence can advance an actual integration state. Discovery never becomes a partnership claim.

## What the loop can coordinate
- product/runtime development
- governance and safety
- truth/provenance
- memory and continuity
- human agency
- global integrations
- creator/publication pipeline
- revenue evidence and finance
- accessibility and multilingual support
- research/learning
- communications/distribution
- robotics/physical AI readiness
- recovery, regression and release checks

## Boundaries
The loop may prepare and verify work. It does not autonomously sign contracts, spend money, donate, purchase, subscribe, transfer funds, expose private memory, or establish a human relationship without required authorization.

## Canonical principle
Verified progress is cumulative. Failed or unverified work remains visible as a gap and is not converted into success.
