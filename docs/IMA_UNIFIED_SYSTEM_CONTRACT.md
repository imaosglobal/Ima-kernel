# IMA Unified System Contract\n\n## Purpose\nIMA is one system, not a collection of disconnected features. Public UI, conversation, personalization, memory, feedback, analytics, capability verification, runtime health, community input and deployment evidence must exchange signals without silently granting autonomous authority.\n\n## Integration rule\nEvery consequential subsystem follows: **observe → validate → connect → adapt → verify → record**.\n\n### Signal sources\n- conversation completion\n- user feedback\n- runtime health\n- memory consent\n- authentication state\n- accessibility and personalization changes\n- navigation and feature use\n- installation/share outcomes\n- capability verification and deployment evidence\n- community contributions\n\n### Signal destinations\n- user-facing personalization\n- learning/feedback state\n- analytics\n- verification evidence\n- operational QA\n- documentation and capability status\n\n## Non-negotiable boundaries\n1. **Human agency:** signals do not authorize irreversible external actions.\n2. **Privacy:** personal memory and learning signals remain consent-bounded.\n3. **Truth before declaration:** code/documentation can describe capability; live verification is required before calling it live.\n4. **No hidden escalation:** a learning signal cannot grant permissions, spend money, publish content, contact third parties, or change governance.\n5. **Traceability:** material changes must have a source, timestamp, and verifiable result.\n6. **Failure is data:** failed operations become testable signals instead of being silently forgotten.\n7. **One canonical runtime:** public deployment evidence must resolve back to the canonical repository state.\n\n## What “IMA improves itself” means here\nIMA may automatically collect bounded product signals, connect related signals, derive low-risk interface adaptations, surface repeated failures, feed verified evidence into capability status, and propose or prepare changes for validation.\nIMA must not silently change governing principles, override consent, expose private memory, deploy unverified changes as truth, or take consequential external action without authorization.\n\n## Cross-part contract\nA new subsystem is incomplete until it declares what it observes, what it may influence, what evidence verifies it, what consent boundary applies, how failure is recorded, and how it can be disabled or rolled back.\n\n## Current implementation\n`ima-ui/src/services/imaLearningBus.js` provides a bounded local learning bus. `imaChat.js` connects chat, feedback, runtime and memory signals to it. `App.jsx` connects navigation, authentication, personalization, accessibility, sharing and installation outcomes and exposes the resulting adaptation state.\n\nThis bus is intentionally local and bounded. It is an integration layer, not an autonomous agent with authority over the product or the user's life.
