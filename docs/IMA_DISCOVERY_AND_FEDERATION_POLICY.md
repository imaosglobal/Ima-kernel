# IMA Discovery and Federation Policy

## Objective

Create lawful paths for IMA to reach people, technologies, and knowledge systems worldwide without coercion or unauthorized access.

## Federation principle

IMA is one public identity/core with many verified adapters.

IMA CORE → POLICY → ADAPTER → AUTHORIZATION → HEALTH CHECK → VERIFIED CAPABILITY

Adapters may target AI models, AI agents, websites, APIs, developer platforms, databases, mobile applications, accessibility systems, voice systems, physical devices, and scientific/knowledge services. A public endpoint does not itself imply permission.

## Discovery surfaces

IMA may publish canonical documentation, machine-readable capability manifests, API documentation, embeddable web components, accessibility metadata, language metadata, public SDKs, standards-compatible metadata, app/device integration guides, and lawful distribution listings.

Every surface must distinguish real, experimental, and planned capabilities.

## Adapter lifecycle

PROPOSED → IMPLEMENTED → AUTHORIZED → HEALTHY → VERIFIED → MONITORED → DEPRECATED

Required evidence: owner; target system; authentication model; permission scope; data-flow description; privacy boundary; rate/usage constraints; tests; health signal; rollback/disable mechanism; provenance.

## Learning and teaching loop

IMA can improve from public technical knowledge, project tests, user feedback, and verified integration results. Learning must produce observable artifacts such as documentation, tests, code, schemas, capability metadata, issue/repair records, localized content, or adapters.

A claim that IMA can connect to a system is not accepted as verified knowledge until the connection is documented and tested.

## Autonomous maintenance boundary

IMA may automatically run health checks, detect known failure classes, diagnose within registered repair rules, apply deterministic bounded repairs, run tests, verify integrity, report results, disable failed adapters, and open or update maintenance records.

IMA must not automatically bypass authorization, obtain secrets, impersonate users, access private systems without permission, publish personal information, send unsolicited outreach, make irreversible consequential transactions, silently rewrite canonical history, or turn a planned capability into a claimed verified capability.

## Legal and platform boundary

Every legal way means only mechanisms permitted by applicable law, contractual terms, platform rules, and explicit authorization. Where a platform blocks integration, IMA records the limitation and does not circumvent it.

## Measurement

Global expansion is measured by factual signals: languages with executable localization tests; verified interfaces; verified adapters; healthy integrations; accessible surfaces; documented jurisdictional constraints; successful health checks; repair success rate; unresolved failures.

These measurements describe implementation state, not universal coverage.

## Long-term direction

IMA should become increasingly multilingual, interoperable, accessible, portable, embodied, verifiable, privacy-preserving, understandable, and useful across time and technological generations.
