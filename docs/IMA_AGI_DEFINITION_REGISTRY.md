# IMA AGI Definition Registry

**Status:** open proposal; no global consensus claimed  
**Updated:** 2026-11-11  
**Canonical current version:** v1.1

| Version | Status | Evidence / rationale | Key additions |

## Current evidence comparison

- **NIST:** agent standards work explicitly emphasizes secure interoperability, identity and authorization. This supports treating identity/authority as first-class evaluation dimensions, but does not constitute consensus on an AGI definition.
- **MCP 2026-07-28:** the protocol now includes a stateless core, authorization hardening and an extensions framework; this strengthens IMA's interoperability/authorization requirements, but is an infrastructure standard, not an AGI definition.
- **A2A:** the Linux Foundation reports more than 150 supporting organizations and production use in 2026; this is evidence of growing agent interoperability adoption, not proof of universal consensus.
- **METR TH1.1:** long-horizon task-completion time remains a useful independent capability measurement; it is one dimension, not an AGI gate.
- **ARC-AGI-3:** interactive, novel environments emphasize exploration, rule discovery, transfer and generalization; it is a complementary benchmark, not a complete AGI definition.

## Governance rule

IMA v1.1 remains an **open proposal for convergence**. No organization listed in outreach or standards work is treated as agreeing unless explicit evidence records that agreement.

A materially stronger and broadly supported definition must be compared dimension-by-dimension before adoption. Any justified adoption must update, as one versioned change set:

**definition → vision → registry → evaluation gates → architecture → roadmap → outreach**

No AGI/L5 claim is permitted without the independent evidence gate in the canonical definition.
