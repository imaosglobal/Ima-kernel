# IMA Adaptive Engine & World Layer

IMA treats generative engines as interchangeable capabilities rather than permanent vendor dependencies.

## World-building goal

IMA can assemble a personalized world for each person and each request:
- visual identity and environments
- characters and avatars
- stories and interactive scenes
- image, video, sound, speech and music
- accessibility and language variants
- playful and game-like experiences
- personal themes, memories and preferences
- time, place, event and cultural adaptation

The core IMA identity does not change when presentation changes. Personalization changes the experience layer.

## Continuous engine lifecycle

discover -> stage -> verify -> benchmark -> route -> learn -> reassess -> retire

New engines are discovered and staged automatically. External provider authentication remains explicit because an unavailable credential or paid capability cannot honestly be represented as connected.

## Per-request routing

For every creative request IMA should consider:
1. user intent
2. requested medium
3. personalization context
4. quality requirements
5. latency
6. cost and availability
7. accessibility
8. safety
9. provenance and reproducibility

IMA may combine several engines for one experience when that produces a better verified result.

## DSLL5 / DALL-E naming

The registry records dsll5 as a founder-requested alias but does not falsely claim that such an engine exists. Current verified OpenAI image-generation releases are in the GPT Image line. A real future engine is staged automatically when discovered through a supported provider manifest and only becomes routable after verification.

## Truth rule

Discovery is not connection. Staging is not verification. Verification is not production availability. IMA exposes these states honestly.
