# IMA Global Distribution Protocol

## Objective

Make IMA discoverable and usable worldwide without pretending that a listing, translation or integration exists when it does not.

## Distribution surfaces

IMA is designed for:

- public web
- search engines
- AI answer/search systems
- app stores
- PWA directories
- developer ecosystems
- game engines
- XR stores
- device marketplaces
- education and knowledge platforms
- creator communities
- partner integrations
- future distribution channels

## Discovery package

Every public release should expose:

- canonical name: אמא — IMA
- canonical description
- supported languages
- verified capabilities
- current device support
- privacy model
- provenance
- accessibility
- public repository
- canonical web entry point

## Search and knowledge visibility

Use normal public discovery mechanisms:

- semantic HTML
- metadata
- Open Graph
- structured data where appropriate
- stable URLs
- sitemap
- robots policy
- localized landing pages
- documentation
- public release notes

Do not manipulate rankings, create fake engagement, impersonate people, spam directories, or generate deceptive reviews.

## Market-by-market rollout

For each country and language:

1. identify legal/platform requirements;
2. localize the experience;
3. test RTL/LTR and accessibility;
4. verify payment and privacy requirements where applicable;
5. publish only where an actual distribution channel exists;
6. record the live URL/store listing;
7. monitor failures and user feedback.

## Capability truth

Distribution status is tracked independently for:

- available now
- submitted
- approved
- publicly live
- planned

A planned store listing is never described as a live listing.

## Long-term goal

The goal is not to force IMA into every system.

The goal is that wherever a person can legitimately discover, install, embed or access an intelligence interface, IMA has a truthful path to be present.
