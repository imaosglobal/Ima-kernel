# IMA Global Distribution and Localization

## Distribution

IMA should be discoverable through lawful, user-controlled channels:
- web
- PWA
- Android
- future iOS/desktop clients
- developer integrations
- embeddable web components
- future device interfaces

Distribution must preserve the same public identity, capability truthfulness, privacy boundary and provenance rules.

## Localization

The product should support language-specific interface, voice, date/time, cultural formatting and accessibility without forking the core identity.

Initial localization targets:
- Hebrew
- English
- Arabic
- Spanish

Localization rules:
- translated UI must not alter safety or provenance semantics;
- source text and translation metadata remain traceable;
- user language preference is separate from private memory;
- right-to-left layout must be tested independently;
- culturally sensitive wording should be reviewed by qualified native-language contributors.

## Marketing

IMA communications must distinguish:
- what is live;
- what is in preview;
- what is planned.

Marketing must not claim universal connectivity, permanent memory, autonomous action or competitor superiority unless the relevant implementation and evidence exist.

## Community growth

Use opt-in channels:
- public documentation
- release notes
- demos
- GitHub discussions/issues
- creator/developer onboarding
- partner integrations
- permissioned affiliate/referral programs

No spam, impersonation, fake reviews, deceptive claims or unsolicited outreach.
