# IMA Global Launch Plan

Status: operational launch framework

## What IMA is now

IMA is an open, human-centered intelligence architecture and product project. Its current implemented foundation includes a public runtime, isolated public memory, a learning loop, applied-skill compilation, explicit learning-gap detection, provenance-oriented governance, interoperability specifications, a web UI, PWA/device continuity work, continuous health checks, and a public contribution path.

Documentation is not treated as proof of runtime capability. A capability is promoted only after implementation and verification.

## Global objective

Make IMA discoverable and usable worldwide, while making contribution a first-class input to its learning system.

The loop is:

DISCOVER -> USE -> QUESTION -> CONTRIBUTE -> VALIDATE -> LEARN -> TEST -> VERIFY -> TEACH -> REPEAT

## Four public doors

1. User: open IMA and ask something.
2. Learner: report what IMA does not know or understand well.
3. Developer: add code, adapters, tests or UX.
4. Researcher/organization: contribute evidence, standards, datasets, interoperability work or domain expertise.

## Global learning intake

Every contribution should carry topic, claim or proposed capability, evidence/provenance, source language where relevant, contributor role, permissions/license, known uncertainty, suggested test, and suggested teaching/application.

Personal/private information is never promoted into shared learning without explicit authorization and applicable privacy controls.

## Verification gate

SUBMITTED -> TRIAGED -> RESEARCHING -> IMPLEMENTED -> TESTING -> VERIFIED -> TEACHABLE -> PROMOTED

A submission may instead become REJECTED, DEFERRED, or REOPENED.

## No artificial virality

Global distribution means making IMA easy to find, try, fork, translate, build on and discuss. It does not mean unsolicited messaging, impersonation, spam, fake endorsements, paid manipulation, or forced adoption.

## First launch message

IMA is open to people who want to use it, question it, improve it, teach it, translate it, test it, or connect it to new technologies.

The project learns from validated contributions rather than treating any single person or model as the complete source of knowledge.

## Success measurements

Measure unique users and returning users, countries/languages represented, questions and learning gaps, contributions, verified contributions, new tests, new adapters, new translations, accessibility improvements, teaching artifacts, resolved and reopened gaps, and verified runtime capabilities.

Do not measure success by claims that cannot be independently verified.
